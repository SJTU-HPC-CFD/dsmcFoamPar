我先给结论，再逐篇拆。

先说总判断：这四篇放在一起，其实给出了一条很清晰的路线。

1. `Gao 2011` 先把节点内 `OpenMP + 数据局部性 + 同步开销` 做对。
2. `McDoniel 2019` 再用 `timer-augmented cost map` 做 **ownership-based** 的 MPI 重划分。
3. `Wu 2005` 说明真正成熟的 DSMC-DLB 主线是 **动态域重划分**，但重划分频率必须严控。
4. `Olson 2010` 说明 `processor timer + feedback` 很有价值，但更适合作为 **触发/调节层**，不是你现在这种 3D 非结构网格 DSMC 的直接主算法。

更关键的一点：这四篇里，没有一篇在走你之前那条 `temporary transfer -> remote collide -> immediate writeback` 的路子。文献主线基本都是 `repartition / ownership migration / boundary shift`，不是“借算一次立刻写回”。

**1. Wu, Tseng, 2005**
[DOI](https://doi.org/10.1002/nme.1232)

这篇的核心不是通信技巧，而是 **动态域分解本身**。它把 DSMC 放在非结构网格上，用 `multi-level graph partitioning` 做动态重划分，并且明确研究了 **什么时候该重划分**。论文里用 `SAR (stop at rise)` 来控制重划分触发频率，这一点很重要，因为作者已经意识到：重划分不是免费操作，频率不对，DLB 本身会吞掉收益。

我读出来的关键信息是：

- 这是 **真 ownership 迁移**，不是临时 task offload。
- 重点是让 processor subdomain 重新划分，而不是把某一轮 collision 借给别的 rank 算。
- 他们报告了：开启 DLB 后，processor 间不平衡大约降到原来的 `1/6 到 1/2`。
- 但他们同时强调，**最优重划分频率会随着问题规模增大而下降**。也就是问题越大，越不能频繁重划分。

这和你现在 mesh-DLB 的实测非常一致：如果你靠 `reconstruct/decompose/restart` 这种外部流程模拟重划分，额外开销会非常大。Wu 这篇支持“重划分是对的”，但也明确要求“重划分必须是低频、真正内嵌、低迁移成本”的实现。

对你当前代码最直接的启发：
- 如果继续做 mesh/ownership DLB，方向是对的。
- 但必须做 **内嵌式 ownership migration**，而不是现在这种高代价外部重构流程。
- 触发策略要像 SAR 一样，严格控制频率，不能每次看见 imbalance 就动。

**2. Olson, Bientinesi, 2010**
[DOI](https://doi.org/10.1016/j.cpc.2010.06.045)

这篇很有意思，因为它不是在建复杂几何 cost map，而是在做 **feedback control**。从官方摘要和 section snippets 看，它的动态负载均衡由两层组成：

- 初始 workload distribution：通过 workload distribution function 的反演得到；
- 动态维护：用每个处理器的执行时间 `τ_i` 作为反馈量，再用 `PID feedback control` 调边界。

它明确说了两件事：

- **单纯粒子数不是好指标**；
- 动态负载均衡开销大约只有 `1%–5%`。

但这篇有一个很大的边界条件：它是 **gridless DSMC**，而且摘要直接写了 `one-dimensional realization`。所以它最自然的适用对象，是能把 workload 沿一个有序方向表达出来的问题。换句话说，它更像“边界位置控制”，不是“任意 3D 非结构网格分区器”。

所以我对它的判断是：

- 它的价值不在“拿来直接抄成你的 3D MPI DLB”。
- 它的价值在于：**用 rank-level runtime 做控制信号**，而不是只盯粒子数。
- 这篇最适合借用的，是“控制论思路”，不是它的几何实现。

放到你这里，更合理的用法是：
- 用 `rank collision wall time / move wall time` 去调 `rebalance trigger`、`rebalance aggressiveness`、或者 `cost weight`；
- 而不是直接用 PID 去拖动当前 scotch/non-structured mesh 的 processor 边界。

**3. McDoniel, Bientinesi, 2019**
[arXiv abs](https://arxiv.org/abs/1902.06040)  
[PDF](https://arxiv.org/pdf/1902.06040)

这篇是四篇里对你最有操作价值的一篇，因为我拿到了全文，而且它刚好卡在 `particle count` 和 `processor timer` 之间。

它先把常见路线拆成三类：

- `particle balancing`：收敛快，但系统误差大；
- `processor timer`：最终更接近真实负载，但空间分辨率太粗，容易 overshoot，需要多轮；
- 它提出的 `TACF`：把两者合起来。

核心公式非常简单，但很强：

- 如果某个 rank 上一步用了时间 `T`，拥有 `N` 个粒子，
- 那它在构造 cost map 时，不是让每个粒子贡献 `1`，
- 而是让每个粒子贡献 `T/N`。

这样做的含义是：

- 仍然保留了粒子分布的 **空间分辨率**；
- 但把真实 runtime 信息灌进了 map；
- 所以它不是纯粒子图，也不是纯 processor coarse timer，而是一个 **有空间分辨率的 runtime-weighted cost map**。

论文里还给了非常实用的工程细节：

- partitioner 用的是 `RCB`；
- cost map 分辨率大约 `1000 cells per processor`；
- 前 100 个 time steps 每 25 步平衡一次，之后每 50 步一次；
- 稳态后在 `16+` processors 开始明显优于 particle-only；
- 到 `64` processors 时，particle balancing 已经让大量 processor “等的时间比算的时间还多”；
- 在他们的 Mach 9 argon jet case 上，稳态可做到约 `2x` 提升，扩展到 `1024` processors。

但这篇不是没有代价。它明确写了一个副作用：**内存不平衡会变大**。平均每个 rank 大约 `650k` molecules，但 TACF 下最大 rank 可到 `1.44M`（64 ranks）甚至 `1.8M`（1024 ranks）。也就是说，它换来的是 wall time 更平衡，但 ownership 不再等粒子数均分。

这篇对你当前 dsmcFoam+ 最直接的意义是：

- 如果你要继续做 MPI-DLB，优先级最高的路线不是 transfer offload；
- 而是做一个 **TACF-style ownership repartition**：
  - 基础空间分辨率来自 cell / particle map；
  - 权重来自 rank-level `move` / `collision` 真实时间；
  - 然后重划分 ownership。
- 这条线和你现在已有的 profile/timer 体系天然兼容。

**4. Gao, Schwartzentruber, 2011**
[DOI](https://doi.org/10.1016/j.compfluid.2010.11.004)

这篇不是 DLB 论文，但对你现在这条线非常关键，因为它在讲一件更基础的事：**如果节点内 kernel 自己就慢，MPI DLB 会被误导。**

从官方摘要和 section snippets 看，这篇主要做了两层优化：

- 串行侧：
  - 用 `three-level Cartesian geometry` 改造几何/寻址；
  - 用更适合 cache 的数据局部性组织 cell-based functions；
  - 这些优化在 cell-based kernels 上能带来 `3.38x–4.36x`，总时间约降 `34%`。
- OpenMP 侧：
  - 他们明确指出 `synchronization points` 和 `critical sections` 是主要瓶颈；
  - 目标是把这些同步点尽量全部拿掉；
  - 在 dual/quad-core 上给到 `1.99` 和 `3.74` 的加速，已经接近理想。

这篇的含义非常直接：

- DSMC 的 shared-memory 扩展性，往往先死在 `critical/atomic/sync` 和坏的数据局部性上；
- 一旦节点内 kernel 没处理好，MPI 层看到的 cost 就不是“物理负载”，而是“实现噪声 + 架构噪声”。

对应到你当前工作，这篇支持你之前做的两件事：
- 修 `move` 路径的 `stagebuf2` / finalize / guard layers；
- 对 `collision` 路径要继续查 `critical section`、临时对象构造、cache locality。

**把四篇合起来，对你当前项目的真正结论**

最值得采纳的不是单篇算法，而是这个组合：

- `Gao 2011`：先把 rank 内核做稳定，尤其是 `move/collision` 的同步和局部性。
- `McDoniel 2019`：再做 `timer-augmented cell cost map -> repartition ownership`。
- `Wu 2005`：再给它配一个低频、严格受控的触发器，别频繁重划分。
- `Olson 2010`：把 PID/feedback 用在“何时重平衡、重多少”上，不要生搬成 3D 分区算法。

换句话说，对 `dsmcFoam+` 最像样的文献路线是：

`shared-memory kernel cleanup`  
-> `per-rank timer + cell-level cost map`  
-> `ownership migration / repartition`  
-> `feedback-controlled rebalance interval/aggressiveness`

不是：

`per-step transfer DLB + remote collision + immediate writeback`

这也是为什么你前面那条 transfer-DLB 线很难获得真实净收益。
