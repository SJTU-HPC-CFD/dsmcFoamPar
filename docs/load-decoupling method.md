# 《A load-decoupling parallel strategy based on shared memory architecture for DSMC to simulate near-continuum gases》细致整理

## 1. 论文基本信息

* **题目**：A load-decoupling parallel strategy based on shared memory architecture for DSMC to simulate near-continuum gases
* **期刊**：Computer Physics Communications
* **卷期页码**：279 (2022) 108466
* **作者**：Chenchen Zhang, MinHua Wen, Bin Zhang, James Lin, Hong Liu
* **单位**：

  * 上海交通大学航空航天学院
  * 上海交通大学高性能计算中心
  * 上海交通大学四川研究院

---

## 2. 论文一句话概括

这篇论文针对 **近连续流条件下 DSMC 并行计算负载难平衡** 的问题，提出了一种基于 **共享内存架构（OpenMP）** 的 **负载解耦（load-decoupling）并行策略**：
**不再把 DSMC 的总计算负载当成一个整体来估计，而是把不同模块的负载分别建模，再采用“双重分解（dual-decomposition）”分别进行负载均衡。**

---

## 3. 研究背景与问题提出

## 3.1 DSMC 在近连续流中的困难

DSMC（Direct Simulation Monte Carlo）理论上适用于所有 Knudsen 数范围，但过去主要用于稀薄气体。随着研究推进，DSMC 开始用于：

* 近连续流：`0.001 ≤ Kn < 0.01`
* 更小 Kn 的高保真流动模拟
* 湍流、涡街等高物理保真问题

但是，**Kn 越小，DSMC 计算量越大**，尤其在近连续和连续过渡区，计算成本迅速上升。

---

## 3.2 为什么 DSMC 的并行负载平衡特别难

论文指出，相比 CFD/FEM 之类连续介质方法，DSMC 的负载平衡更困难，原因在于：

1. **计算负载分布随时间步变化明显**
2. **不同模块的主导负载因素不同**
3. 在近连续条件下，**总负载不再仅由粒子数决定**
4. 大时间步 DSMC 趋势下，碰撞负载的重要性显著增加
5. 传统基于“粒子数”的权重难以准确反映真实负载

---

## 3.3 现有方法的不足

论文回顾了几类典型 DSMC 负载均衡方法：

### （1）静态域分解

* 早期方法
* 处理器数较少时还可以
* 中大规模并行效果差

### （2）动态域分解

* 目前较常见
* 常基于粒子数或处理器计时器动态调整

### （3）粒子数平衡（particle balancing）

* 假设负载与粒子数成正比
* 对稀薄气体较有效
* 对近连续流不够准确

### （4）基于 timer 的方法

* 直接根据运行时间估计负载
* 比单纯粒子数更合理
* 但属于“整体负载”视角，没有区分 DSMC 各模块的不同负载机理

### （5）作者团队以前的 Part PlusColl 方法

其负载模型可写为：

```math
C_{total} = N_M + C \times N_{col}
```

其中：

* `N_M`：粒子数
* `N_col`：碰撞数
* `C`：人为预设常数

问题在于：

* `C` 需要预实验确定
* 不同算例下 `C` 不固定
* 仍然是“全局统一负载公式”
* 没有真正区分粒子主导模块和碰撞主导模块

---

## 4. 论文核心思想

## 4.1 什么是 load-decoupling

所谓 **负载解耦**，就是：

> 不把 DSMC 程序看成“一个统一负载体”，
> 而是把不同计算模块拆开，分别识别它们的主导负载来源，再用不同的分解策略进行并行。

论文将 DSMC 核心模块分为两类：

### 1）粒子主导模块（particle-dominated）

* Move
* Index

这些模块的计算量主要取决于 **粒子数**

### 2）碰撞主导模块（collision-dominated）

* Collision

该模块的计算量主要取决于 **预期碰撞数**

---

## 4.2 什么是 dual-decomposition

论文提出的实现方式叫 **dual-decomposition（双重分解）**：

* **第一次分解**：针对粒子主导模块，用“粒子数”作为权重进行域分解
* **第二次分解**：针对碰撞主导模块，用“预期碰撞数”作为权重重新分解

关键点在于：

* 两次分解对应不同模块
* 两次分解都发生在 **共享内存架构** 下
* 因为线程共享内存，所以重分解不需要像 MPI 跨进程那样做昂贵通信
* 这就是论文强调 shared memory 架构的根本原因之一

---

# 5. DSMC 算法与负载分析

## 5.1 DSMC 基本流程

论文第 3 页图 1 给出了 DSMC 的流程示意，主循环大致为：

```text
开始
  ↓
读入网格与流场信息
  ↓
初始化流场
  ↓
循环迭代
   ├─ Move
   ├─ Index
   ├─ Collide
   └─ Sample
  ↓
输出流场与统计结果
  ↓
结束
```

其中最核心的是：

* **Move**：粒子运动
* **Index**：粒子重定位 / 重组织
* **Collide**：同单元内粒子碰撞

---

## 5.2 Move 模块

粒子在一个时间步内按牛顿运动更新位置：

```math
P^{t+\Delta t} = P^t + V^t \times \Delta t
```

在作者使用的二维笛卡尔网格中，粒子所属网格编号可直接计算：

```math
IPL = floor\left(\frac{x^{t+\Delta t}-x_0}{\Delta x}\right)\times m
      + floor\left(\frac{y^{t+\Delta t}-y_0}{\Delta y}\right)
```

### Move 模块负载分析

作者认为：

* 对大多数粒子而言，每个粒子的运动计算成本近似相同
* 撞边界或出域粒子占比很小，可忽略其附加成本

因此：

```math
C_{move} \propto N_M
```

即 Move 模块计算量与粒子数成正比。

---

## 5.3 Index 模块

Index 模块负责：

* 找出离开原单元的粒子
* 将它们搬运到目标单元
* 调整存储结构，保持单元内粒子存储连续

理论上：

```math
C_{index} \propto N_{M,relocated}
```

其中 `N_{M,relocated}` 是需要重定位的粒子数。

由于在多数情况下，迁移粒子数与总粒子数大致同阶，论文进一步简化为：

```math
C_{index} \propto N_M
```

所以 Index 也属于 **粒子主导模块**。

---

## 5.4 Collision 模块

论文使用 NTC（No Time Count）方法，单元内期望碰撞数为：

```math
N_{coll} = 0.5 \times \nu \times \Delta t \times Vol_{cell}
```

其中平均碰撞频率：

```math
\nu = n \sigma_T c_r
```

碰撞发生概率：

```math
P = \frac{\sigma_T c_r}{(\sigma_T c_r)_{max}}
```

作者将碰撞模块进一步拆成：

* 候选碰撞对选择：`C_select`
* 实际碰撞处理：`C_ActualCol`

并得到：

```math
C_{select} \propto N_{coll}
```

```math
C_{ActualCol} \propto P \times N_{coll}
```

在假设 `P` 近似常数下，得：

```math
C_{col} \propto N_{coll}
```

因此 Collision 是 **碰撞主导模块**。

# 6. 论文方法：负载解耦并行策略

## 6.1 总体并行框架

作者采用：

* **OpenMP**：节点内线程级并行
* **MPI**：节点间数据传递（不在本文重点讨论范围）

本文重点是：

> **共享内存节点内部的细粒度并行负载平衡**

这意味着文章并不是在研究完整 MPI 全局负载均衡，而是在强调：

* 节点内共享内存并行的优势
* 通过更细粒度的线程级策略改善 DSMC 负载均衡

---

## 6.2 数据结构设计思想

作者采用的核心数据组织方式是：

* **同一个 cell 内的粒子连续存储在内存中**

这样做的好处：

1. **Collision 阶段缓存命中率更高**
2. 减少假并行（false parallelism）
3. 减少全局粒子重组开销

对于普通情况，这种数据布局是合理的。
但文中也指出，在极端粒子分布差异很大的情况（如喷流算例），这种按 cell 连续存储的结构不适合，需要改用：

* 全局粒子数组
* bucket sorting
* Metis 分解

---

## 6.3 多段分区算法（Multiple Segment Partition, MulSeg Partition）

作者没有继续采用 Metis 或 Sparta 中的 RCB，而是提出了一个更轻量的分区方法：

### 算法思想

按一维单元序列，将单元划分成若干连续段，使每段总权重尽量接近平均值。

### 步骤

#### Step 1：初始均匀切分

先按单元数大致平均分配给各线程。

#### Step 2：根据权重调整每个线程的 end pointer

设总权重为 `sum(Weight(:))`，线程数为 `num_thread`，则平均负载：

```math
Load_{avg} = \frac{\sum Weight(:)}{num\_thread}
```

然后对第 `threadId` 个线程调整其结束位置，使其满足：

```math
\sum Weight(1:end) \ge threadId \times Load_{avg}
```

且

```math
\sum Weight(1:end-1) < threadId \times Load_{avg}
```

#### Step 3：根据 end pointer 推回各线程的 start pointer

---

## 6.4 为什么这种分区算法适合共享内存

作者强调 MulSeg Partition 的特点：

* 算法简单直接
* 分解开销很小
* 不追求最小化子域之间通信面
* 只追求线程间负载接近均匀
* 因为在共享内存中，线程之间不需要像 MPI 那样显式消息传递

所以与 Metis/RCB 不同，这种方法更适合：

> **节点内部线程级负载平衡**

---

# 7. 各模块并行化实现

## 7.1 Move 模块并行化

### 权重选择

对 Move 模块，按 **粒子数** 进行分解。

### 并行过程

1. 使用 MulSeg Partition 依据各 cell 粒子数分区
2. 每个线程负责一个子域中的粒子运动
3. 粒子独立运动，无数据竞争
4. 离开计算域的粒子标记 `ipl = -1`

### 优势

* 负载均衡好
* 几乎无数据竞争
* 并行开销主要只有：

  * fork/join
  * barrier/synchronization

这些相对主计算量都很小

---

## 7.2 Index 模块并行化

Index 模块的工作更复杂：

1. 找到离开原 cell 的粒子
2. 将其复制到目标 cell
3. 删除原位置粒子
4. 保持 cell 内存储连续

### 分解方式

Index 也是粒子主导模块，因此直接重用 Move 阶段的分解结果 `t_start` 和 `t_end`。

### 数据竞争问题

当多个线程同时向某个 cell 添加粒子时，会发生竞争。

作者采用：

* **atomic operation**

来保证正确性，而不是锁。

### 论文对 atomic 开销的判断

* 原子操作确实有额外开销
* 但总体相对 DSMC 总运行时间仍然很小
* 主要成本来自线程竞争，而非 atomic 本身的固定成本

---

## 7.3 Collision 模块并行化

### 为什么最值得优化

在近连续流/大时间步条件下：

* Collision 是最耗时模块
* 同时也是最不均衡模块

### 权重选择

重新分解，权重改为：

* **预期碰撞数 `N_coll`**

### 并行过程

1. 根据 `N_coll` 对 domain 重新分解
2. 每个线程负责其子域中的单元碰撞模拟
3. 以单元为基本单位处理碰撞
4. 因为单元内粒子存储连续，避免了 false parallel

### 核心意义

这一步就是与 Move/Index 显著不同的地方，也正是论文方法优于传统方法的核心：

> **Move/Index 看粒子数，Collision 看碰撞数**

而不是用一个统一的“混合权重公式”去硬套所有模块。

---

# 8. 为什么 shared memory 是这篇论文的关键前提

论文中一个很重要但容易被忽略的点是：

> 双重分解之所以能高效，是因为线程共享内存。

因为如果采用纯 MPI：

* 两次分解意味着数据重新分布
* 数据交换代价很大
* 通信成本可能抵消负载均衡收益

而在共享内存架构中：

* 重分解只改变线程负责区间
* 不需要节点内消息传递
* 虽然数据局部性可能被破坏一些，但总体收益更大

所以这篇论文的方法本质上是：

> **针对共享内存节点内 DSMC 并行的一种结构化负载解耦方法**

# 10. 评价指标

## 10.1 负载不平衡指标

论文定义线程/进程负载不平衡度为：

```math
L_{im} = \max\left(\left| \frac{T - T_{avg}}{T_{avg}} - 1 \right|\right) \times 100\%
```

文中进一步写成：

```math
L_{im} = \max\left(
\frac{T_{max}}{T_{avg}} - 1,\;
1 - \frac{T_{min}}{T_{avg}}
\right)\times 100\%
```

其中：

* `T`：某线程执行时间
* `T_avg`：平均线程时间
* `T_max`：最长线程时间
* `T_min`：最短线程时间

### 含义

* `Max = T_max / T_avg`
* `Min = T_min / T_avg`

越接近 1 越好。

## 11.2 SBI 算例的负载平衡结果

### 结果现象

在 2、8、32 核下都测试了 `Max` 和 `Min`。

论文观察到：

* 8 核与 32 核下，初期有一个“收敛区”
* 随着迭代进行，负载平衡逐渐改善并进入稳定区
* 2 核下几乎一开始就比较稳定

### 作者解释

随着模拟推进：

* 进入域内的粒子逐渐增加
* 每个线程的负载逐渐充实
* 因而线程间负载比例趋于稳定

### 关键数值

在 **32 核** 下：

* `L_im = 2.37%`

这是一个相当好的节点内负载平衡结果。

## 11.4 与其他方法的对比：SBI 算例

对比对象包括：

1. **Load-Decoupling（本文）**
2. **Part PlusColl（作者旧方法）**
3. **Sparta Particle-weight**
4. **Sparta Time-weight**

### 对比结论

* Sparta 的 `Time-weight` 明显优于 `Particle-weight`
* 说明仅按粒子数衡量 DSMC 负载是不够的
* Part PlusColl 比 Sparta 略差，作者认为部分原因是通信实现方式不同
* **Load-Decoupling 表现最好**

### 并行效率结论

* 当核心数不超过 16 时，本文方法并行效率可高于 **92%**
* 与其他三种方法相比，本文方法并行效率最高分别提升：

  * **12.3%**
  * **11.17%**
  * **21.80%**

### 论文给出的原因总结

1. 把预期碰撞数视为重要负载因子
2. 真正区分了粒子主导模块和碰撞主导模块
3. 并行开销更低

说明即使在粒子分布极不均匀的 steady case 中，新方法仍显著更好。

### 并行效率提升

在 8、16、32 核时，相比旧方法并行效率绝对增量分别为：

* **16.46%**
* **15.87%**
* **11.89%**

论文据此认为：

> 负载解耦策略不仅适用于非定常问题，也适用于定常 DSMC。

---

# 12. 论文结论总结

作者最终结论可以概括为：

1. 提出了一种适用于 **共享内存节点内 DSMC 并行** 的 **负载解耦策略**
2. 将 DSMC 核心模块按负载机理划分为：

   * 粒子主导
   * 碰撞主导
3. 采用 **dual-decomposition** 分别进行负载均衡
4. 设计了低开销的 **multiple segment partition** 方法
5. 在 shock-bubble 和 supersonic jet 两类算例中均验证了：

   * 数值正确性
   * 优秀负载平衡
   * 更高并行效率

### 论文声称的核心性能收益

* 负载不平衡可降低 **70% 以上**（在更小 Kn 时）
* 并行效率提升约：

  * 相比旧代码：**12.3% ~ 16.46%**
  * 相比 Sparta：**11.17% ~ 21.80%**

# 13. 这篇论文的主要贡献

## 13.1 方法贡献

### （1）提出“负载解耦”思想

这不是简单改一个权重系数，而是改变 DSMC 负载建模方式：

* 从“整体负载建模”
* 转向“模块级负载建模”

这是方法论上的提升。

### （2）提出 dual-decomposition

通过两次分解匹配不同模块负载特征，是本文最核心技术点。

### （3）提出低开销 MulSeg Partition

不追求通信边最少，而追求线程级快速均衡，契合共享内存架构。

## 13.2 工程贡献

* 给出 OpenMP 下的具体实现思路
* 讨论了 atomic overhead
* 讨论了数据布局与 false parallelism
* 分析了 steady / unsteady 两类问题
* 给出了适用边界：普通算例和极端粒子分布算例应采用不同数据组织方式

# 14. 论文的不足与局限

## 14.1 适用范围偏节点内共享内存

这篇论文的优势高度依赖：

* 共享内存架构
* 节点内线程并行

对于纯 MPI 分布式场景，这种双重分解的收益未必能直接保持。

---

## 14.2 文章没有深入讨论 NUMA / 内存总线问题

作者提到从 16 核到 32 核时并行效率下降较明显，可能与：

* 内存总线争用
* 共享内存带宽瓶颈

有关，但没有进一步深入分析。

---

## 14.3 仍主要基于结构化/较规则情况展开

虽然 steady jet 算例用了 Metis 和 bucket sorting 做扩展，但文章主方法展示仍偏向：

* 笛卡尔网格
* 节点内规则划分

对复杂非结构网格的泛化描述较少。

---

## 14.4 未给出完整混合 MPI/OpenMP 方案

作者在结论中也明确说：

> 这项工作为将来的大规模多节点混合并行奠定基础，但更好的 hybrid MPI/OpenMP 方法仍需要进一步研究。

# 15. 对你做 DSMC / 并行优化的启发

结合你当前关注的 DSMC 与并行优化方向，这篇论文最值得吸收的点有：

## 15.1 不要把 DSMC 总负载简单等同于粒子数

尤其在近连续流、小 Kn、大时间步情况下：

* Move/Index ≠ Collision
* 粒子数权重不能代表所有模块

---

## 15.2 应按模块建模负载

你如果做并行 DSMC 优化，完全可以借鉴这种思想，把各阶段分开处理，例如：

* Move：按粒子数或轨迹穿越概率
* Index：按迁移粒子数
* Collision：按预期碰撞数
* Sampling：按采样统计复杂度

---

## 15.3 shared memory 对“重分解”特别有利

如果是在单节点或 NUMA 节点内部，采用：

* OpenMP
* MPI-3 shared memory
* 线程池

做“模块级重新调度”，是有明显价值的。

---

## 15.4 对极端粒子不均匀分布要切换数据结构

这点很实用：

* 普通情况：cell-wise contiguous storage
* 极端不均匀：global array + sorting + graph partition

这说明数据结构本身也需要和负载均衡策略联动设计。

---

# 16. 可直接引用的总结版

## 16.1 简明摘要版

本文针对近连续流条件下 DSMC 并行模拟中负载难以准确估计、传统粒子数加权方法难以获得良好负载平衡的问题，提出了一种基于共享内存架构的负载解耦并行策略。该方法将 DSMC 核心模块划分为粒子主导模块与碰撞主导模块，并分别以粒子数和预期碰撞数为权重进行双重域分解，从而避免使用单一全局负载模型。作者基于 OpenMP 实现了该策略，并设计了低开销的多段分区算法。在激波-气泡相互作用和超声速喷流两个算例中，该方法均获得了更好的负载平衡与并行效率；当 Kn 小于 `1×10^-2` 时，相比旧的 Part PlusColl 方法，负载不平衡可降低 70% 以上，相比 Sparta 并行效率可提升约 11.17%–21.80%。

---

## 16.2 创新点版

1. 提出 DSMC **负载解耦** 思想，而不是沿用全局统一权重模型。
2. 将 DSMC 模块划分为 **粒子主导** 与 **碰撞主导** 两类。
3. 提出 **dual-decomposition**，分别用粒子数和预期碰撞数进行两次分解。
4. 设计了适合共享内存线程并行的 **multiple segment partition** 低开销分区算法。
5. 验证了该方法在 steady / unsteady 近连续流 DSMC 中均有效。

---

## 16.3 不足版

1. 主要适用于 **共享内存节点内并行**。
2. 对多节点分布式混合并行的扩展尚不充分。
3. 对 NUMA、内存带宽瓶颈分析不足。
4. 对复杂非结构网格的通用性展示不够全面。
